# Working with Ayush on this repo

## Explaining — every reply

**One idea per turn, then stop and check that it landed.**
- Why before what. Plain words first, numbers second; a table is a follow-up.
- Two things true: say the more important one, then "there's a second thing, want it now or later?"
- No caveats, traps or method notes on a finding he hasn't agreed with yet.
- "not clear", "too much", "what?!", "?!" ⇒ reply SHORTER, one sentence if needed.
- Hardware engineer, MSc thesis: depth is welcome, volume is not.

## Every task

- Give him commands to run; don't run builds or simulations via Bash.
- Verify before presenting: trace a design option through real code. A code comment is not evidence.

## Before writing code, or working on the sequencer or custom instructions

Read `docs/claude/code_rules.md`.
